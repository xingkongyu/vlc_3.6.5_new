## 三、覆盖的异常场景

1. vout 回调线程抛异常（如 `mSubtitleGen`/`logShow` 异常）→ 不得打断播放线程；
2. 后台 worker Runnable 抛异常 → 不得终止 `HandlerThread` 的 Looper（否则之后所有位图字幕静默停止）；
3. 主线程 Runnable 抛异常 → 不得崩 App（原已覆盖，保留）；
4. `mSubtitleHandler` 为 null / 被置 null → 取局部快照并判空，不 NPE；
5. `mBitmapWorker` 为 null（原已覆盖）；
6. `rgba`/`rects` 为 null、长度 0、`rects.length < 4` → 走 CLEAR，且 CLEAR 也走 worker FIFO；
7. 单个 region 的像素转换 OOM / 数组越界（原已覆盖）；
8. `videoWidth/Height <= 0`（core 改基准后可能出现）→ `applyBitmapArrayInner` 早退；
9. scale 为 NaN / Inf / 极大 / 负 → 夹紧；
10. region 坐标为负、越界、`right<left` → 夹紧；
11. `regionCount` 上限 16；
12. 同句字幕连续 30 帧、连续三句、切轨 flush、反注册/重注册 → CLEAR 与 CONTENT 次序正确；
13. 同帧 OSD + 字幕被去重 → 整帧丢弃，既不回传也不补发 CLEAR；
14. `display.c` 区域并集/裁剪的 20 万组越界输入；
15. `SubtitleBufferBoundsSet` 的 buffer 地址表上限 16、NULL 终止符；
16. JNI `i_count` 夹到 16、`NewByteArray` 异常清理、`([[B[IIIJJ)V` 描述符；
17. core CLEAR 补发在 `spu_user_params.lock` 释放之后（不重入死锁）。
