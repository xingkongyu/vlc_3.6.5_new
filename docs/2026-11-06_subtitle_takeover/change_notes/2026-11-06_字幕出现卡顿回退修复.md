## 一、现象与范围

用户反馈：当前版本播放时**字幕一出现画面就卡一下**，而基线版本 `libvlc-release-20261102_112606_baseline.aar` 是修好的；怀疑 core 在处理字幕数据时占用时间导致掉帧。设备 adb `42f6b29cec0fe663`。

本轮只改 core 两个文件；App / JNI / Java 均未改。

## 三、根因（五层，按对「字幕出现即卡」的贡献排序）

| 层 | 基线（不卡） | 回退版（卡） |
|---|---|---|
| L4 同句去重 | `SpuRenderSubpictures()` 按 `(order,start,stop)` 判同句则整条跳过渲染 | 无去重；`spu_Render()` 逐帧（24~30fps）重跑 `SpuRenderRegion()` |
| L5 不缩放 | 接管时 `scale = spu_scale_unit()` | PGS 1080p→4K 走 swscale 2 倍放大；基线计时日志实测 `render region 499x61 took 72950us`、`826x62 130519us`、`557x144 162162us` → **字幕出现瞬间卡一下** |
| L3 零拷贝/不上屏 | region 渲染到临时 detach 链表，回调传 `p_pixels`，回调完释放，不进 `output` | 先渲染进 `output`，`SpuBitmapBridgeNotify()` 再 `malloc(w*h*4)` + 逐行 `memcpy`/逐像素重着色后丢弃 |
| 回调去重 | 每条字幕只回调一次 | `b_has_last` 只管 CLEAR，内容每帧回传 → App 每帧做 ~9ms 预乘转换 + ImageView 重绘 |
| L1 清屏 | `SubtitleBufferBoundsGet/Set` + `SubRectUnion` 按 buffer 脏区清字幕行 | 「凡需重绘一律整屏 memset」4K 33MB ≈ 40ms；且删掉了空壳 subpicture 早退（4K Surface 空锁实测落后 ~250ms）与 `SubtitleRegionToBounds()` 空矩形初始化 |

## 四、改动内容（增量移植，**未整文件覆盖**）

> 不能整文件覆盖基线：会连带删掉 11-06 的 CLEAR 补发 / 黑边原色分离 / try-catch 加固；且回调协议已变（基线 5 参 `pf(data, vlc_spu_bitmap_t*, count, start, stop)` vs 当前 8 参 `pf(data, n, pp_rgba, p_rects, w, h, start, stop)`），覆盖会导致 JNI/App 崩溃。

### `src/video_output/vout_subpictures.c`

| 位置 | 改前 | 改后 |
|---|---|---|
| `spu_user_params` 结构 | 只有 `b_has_last` | 增 `i_last_order/start/stop` 记录上次回传字幕身份；注释同步更正 |
| `vlc_spu_set_bitmap_listener()` | 注册时只清 `b_has_last` | 同时重置三个身份字段，避免切轨后误判同句 |
| `SpuBitmapBridgeNotify()` CLEAR 分支 | 只清 `b_has_last` | 同步清空身份 |
| `SpuBitmapBridgeNotify()` 内容分支 | 只置 `b_has_last = true` | 记录 `p_output->i_order/start/stop` |
| `SpuRenderSubpictures()` 开头 | 无 | 取 `b_bitmap_takeover` 快照 + 声明 `b_skipped_subtitle` |
| 循环内 | 每个字幕 subpic 无条件渲染 | 按 `(order,start,stop)` 判同句 → 整条 `continue`，置跳过标志 |
| 循环内 original size 兜底之后 | `output` 身份/基准取 `fmt_dst`（4K）与 `subpicture_New` 默认值 | 接管时改为 `subpic->i_order/start/stop` 与 `subpic->i_original_picture_*`，保证 scale=unit 后坐标基准一致、去重身份一致 |
| scale 计算之后 | 直接用 4K 放大 | 接管时 `scale = spu_scale_unit()`，只保留色度转换 |
| 函数末尾 | 一律走 `SpuBitmapBridgeNotify(spu, output)` | 去重帧直接丢弃 `output` 返回 NULL（不发 CLEAR、不把同帧 OSD 误当字幕回传） |

### `modules/video_output/android/display.c`

| 位置 | 改前 | 改后 |
|---|---|---|
| `SubtitleRegionToBounds()` | `regions=0` 时输出矩形未初始化（栈值） | 开头先置空矩形 |
| 函数区 | 只有注释说明「一律整屏清除」 | 补回 `SubRectUnion()` / `SubtitleBufferBoundsGet()` / `SubtitleBufferBoundsSet()` 三个静态函数（结构体字段 `buffer_bounds` / `p_sub_buffer_bounds` 与 free 逻辑本就还在，无需改结构） |
| `SubpicturePrepare()` | `ARect memset_bounds` 单变量 | 增 `clear_bounds` |
| lock 之前 | 无空壳早退 | 空区域且屏幕无残留时直接 return，避免 4K Surface 空锁 |
| 清除段 | `CLEAR full rect` 整屏 memset | `CLEAR rect=` 按 buffer 残留区 ∪ 本帧区域清除，含上下界/越界夹紧；blend 后 `SubtitleBufferBoundsSet()` 记录 |

## 八、风险与边界

- 去重身份取 `(order,start,stop)`，与基线一致；两条不同字幕三值全同的极端情况会被跳过（上游同值即同一 subpic，风险低）。
- 多个字幕 subpic 同帧时，`output` 身份取最后一条字幕；字幕被去重且同帧有 OSD 时 `output` 整体丢弃，接管模式下 OSD 本来也不上屏。
- 若 region 非 RGBA 导致 `SpuBitmapBridgeNotify()` 返回 false，会退化为内置渲染且不去重（功能安全，性能回到旧路径）。
- `display.c` 脏区表按 buffer 地址记录，地址种类上限 16，超限整表重置（最坏多清一次，不越界）。
