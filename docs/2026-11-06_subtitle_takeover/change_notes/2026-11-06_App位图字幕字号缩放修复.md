# 2026-11-06 App 位图字幕字号缩放修复（含真机复验）

## 1. 现象与范围

位图字幕（PGS）接管后显示、颜色均正常，但**设置面板的字号档位对位图字幕完全不生效**。

本次按用户选定的「最小修复」执行：只改 App 两处 Java，**不碰 core、不重编 AAR**；颜色保持现状（core bridge 的 `SpuUserColorGet()` alpha 遮罩改色不动）。

前置依赖：JNI 方法描述符修复后的 AAR `libvlc-release-20261106_095230.aar`（见 `2026-11-06_位图字幕JNI签名修复.md`），App `vlc/build.gradle` 以 `api fileTree(dir: 'libs', include: ['*.jar','*.aar'])` 通配引用。

## 2. 根因

1. core `vout_subpictures.c` 的 `SpuUserScaleGet()` 已无调用点，bridge 回传的 RGBA 位图**未经 core 缩放**；`:sub-scale` 媒体选项与 `setSubtitleScale()` 对回传位图无效。
2. App `VlcVideo.applyBitmapArray()` 原本只按视频/视图比例 `sx/sy` 绘制，`mSubtitleBitmapScale` 计算了却没被使用 → 字号设置形同虚设。
3. `VideoActivity2.getSubtitleSize()` 原返回 `16 + i * 8`，与 `set_subsize()` / `VlcVideo.setSubtitleSize()` 的档位映射 `24/36/48/60/70/80/90` 不一致：默认档 i=1 返回 24，会被换算成 `24/36 = 0.667`，一旦缩放生效，开播即把字幕缩小三分之一。

## 3. 修改内容（改前 → 改后）

| 文件 | 位置 | 改前 | 改后 |
| --- | --- | --- | --- |
| `D:\workspace\A14\a14_2\publicversion\vlc\src\main\java\com\hhhc\vlc\VlcVideo.java` | `applyBitmapArray()` 约 2966-2984 | 只有 `sx/sy` | 新增 `final float userScale = mSubtitleBitmapScale > 0f ? mSubtitleBitmapScale : 1.0f;`，并计算整句字幕「底边中点」锚点 `anchorX/anchorY` |
| 同上 | 约 3014-3032 | `dstW = round(w*sx)`、`dstH = round(h*sy)`、`x = rects[i*4]*sx`、`y = rects[i*4+1]*sy` | 尺寸乘 `userScale`；坐标改为 `anchor + (原坐标 - anchor) * userScale`，多 region 同比缩放、不散开；`userScale==1.0` 与原逻辑等价 |
| 同上 | 约 3054-3058 | `bitmap draw: ... scale=sx/sy ...` | 追加 `user=` 便于验证 |
| `D:\workspace\A14\a14_2\publicversion\app\src\main\java\com\hhhc\mediacenter\VideoActivity2.java` | `getSubtitleSize()` 约 643-652 | `return 16 + i * 8;` | `switch(i)` 返回 `24/36/48/60/70/80/90`，默认 36 |

说明：`VlcVideo.setSubtitleSize(int)`（约 2482-2501）原本就把档位 0~6 映射为上述 sp 值，`default` 分支把传入值直接当 sp。因此 `getSubtitleSize()` 返回 60 时走 `default` 得到 60f，与 `set_subsize(3)` 走 `case 3` 得到 60f 完全一致，两条调用链（`onPlayPre` 回调 / 设置面板）不再打架。

副作用：`getSubtitleSize()` 同时用于文本字幕开播默认字号，默认档由 24sp 变为 36sp；如需单独回退，只还原 `VideoActivity2.java` 这一处即可。
