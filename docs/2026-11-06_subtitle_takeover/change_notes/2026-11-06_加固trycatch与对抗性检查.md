# 2026-11-06 加固：try-catch 与对抗性检查

## 范围

不改功能、不改 core / JNI（**无需重编 AAR**），只对 2026-11-06 的 App 改动补异常兜底与数值边界。归档提交前的一轮防御性加固。

## 加固清单

| # | 位置（`VlcVideo.java` 除特别注明） | 原风险 | 改后 |
|---|---|---|---|
| 1 | `applyBitmapArray()` | 主线程方法体前半段（`mVideoLayout.getWidth()`、锚点循环、`ensureBitmapViews`）无 try-catch；`mVideoLayout` 可能为 null，`bitmaps/rects` 未校验 | 拆成 `applyBitmapArray()`（整体 `try-catch(Throwable)`，失败时 `hideBitmapSubtitle()` 清屏）+ `applyBitmapArrayInner()`；inner 前置校验 bitmaps/rects 非空、`videoWidth/Height>0`、`!mDestroyed`、container 非空；尺寸获取加 `mVideoLayout != null` 保护 |
| 2 | `applyBitmapArrayInner()` 单 region 循环 | `mBitmapSubtitleViews.get(i)` 在 try 外，`ensureBitmapViews` 扩容失败时越界会抛 | 把 `get(i)` 移入 try；catch 内改用带下标检查的隐藏兜底，不再引用 try 内局部变量 |
| 3 | 绘制收尾循环 | 隐藏多余 View / container 的循环在 try 外 | 整体 try-catch，失败只记日志，不影响已绘制内容 |
| 4 | `userScale` / `dstW,dstH` / `x,y` | `mSubtitleBitmapScale` 若被外部路径改成 NaN/Infinity/超大值，`Math.round` 会得到 `Integer.MAX_VALUE` 的 LayoutParams；`videoWidth` 极小会让 `sx` 极大；异常 rect 会让锚点极大 | 新增 `clampSubtitleScale()`（非有限值 → 1.0，范围 0.1~5.0）、`clampSubDim()`（上限 `viewSize*6`）、`clampSubPos()`（±`viewSize*6`），全部用 long 计算避免乘法溢出 |
| 5 | `subtitleScaleFromSp()` / `setSubtitleSize()` | `default: sp = size` 允许任意 int，NaN/Infinity/负值会传给 `TextView.setTextSize` 与 sub-scale | `subtitleScaleFromSp` 加非有限值与 `<=0` 保护；`setSubtitleSize` 把 sp 夹紧到 `(0, 200]`，`setTextSize` 加 try-catch |
| 6 | `rgbaToPremultipliedArgb()` | `new int[n]`（最大 8MB）抛 `OutOfMemoryError` 时，`catch(Exception)` 抓不住，会终止后台 HandlerThread 的 Looper | 单独 `catch(OutOfMemoryError)` → 记日志并返回 null，让该 region 跳过；上层 `buildBitmapArray` 已有 `catch(Throwable)` 双保险 |
| 7 | `applyBitmapSubtitleToMedia()` | `media.addOption` 无兜底；`mSubtitleBitmapScale` 异常会注入 `:sub-scale=NaN/Infinity` | try-catch(Throwable) + 注入前 `clampSubtitleScale()`；媒体选项失败不阻断起播 |
| 8 | `hideCustomSubtitle()` | 本次新加的 `mSubtitleGen.incrementAndGet()` 若因后续 View 异常而跳过，在途绘制任务会复活旧字幕；只 GONE 不清文本，别处置 VISIBLE 时旧句会重现 | 代际递增提到 try 外**无条件先执行**；文本清屏加 `setText("")` 并单独 try-catch；位图清屏独立调用，互不连带 |
| 9 | `onSubtitleText()` 主线程 Runnable | 本次改的空文本分支无兜底，未捕获异常会崩 App | Runnable 整体 try-catch(Throwable)，单条回调失败只影响这一句 |
| 10 | `VideoActivity2.playVideo()` | 本次新增的切集清屏无兜底，View 可能已随窗口销毁 | try-catch(Throwable)，清屏失败只记日志，不阻断起播 |

## 对抗性检查表

| 异常场景 | 期望行为 | 依据 |
|---|---|---|
| `rgba=null` / `rects=null` / `rects.length<4` | 走 CLEAR 队列，隐藏字幕，不崩 | `onSubtitleBitmaps` 300-325；CLEAR Runnable 内 try-catch |
| 单 region `w<=0` / `h<=0` / `px=null` / `px.length<w*h*4` | 该 region 跳过并记 INVALID，其它 region 照常 | `buildBitmapArray` 用 long 算 need 并逐块校验 |
| `w*h` 在 int 上溢出 | 不被绕过 | `n64=(long)w*h`，`n64*4 > rgba.length` 校验 |
| region 数 > 16（JNI 上限 100） | 只处理 16 个，不越界 | `regionCount()` 三处统一上界 |
| `w*h > 1920*1080` | region 丢弃，不 OOM | `MAX_SUB_PIXELS` |
| `int[]` / Bitmap 分配 OOM | 后台线程不终止，该 region 跳过 | 本轮 #6 + 既有 `catch(OutOfMemoryError)` / `catch(Throwable)` |
| 用户缩放为 NaN / Infinity / 0 / 100 | 夹紧到 0.1~5.0 或非有限→1.0，LayoutParams 有上限 | 本轮 #4/#5 |
| `videoWidth=1` 导致 sx 极大 | dstW/dstH、x/y 被 clamp 到 viewSize*6 内 | `clampSubDim` / `clampSubPos` |
| 切轨期间回调到达（vout → worker → 主线程） | 代际不符即丢弃，不把旧字幕画回 | `mSubtitleGen` 三层快照校验 |
| CLEAR 与内容回调同时排队 | 严格 FIFO，清屏最后生效 | 两者同走 worker 队列 |
| View 已 detach / `mDestroyed` / container 为 null | 直接返回或由外层 catch 清屏 | 本轮 #1 前置校验 |
| 主线程绘制抛异常 | 不崩 App，清屏兜底 | `applyBitmapArray` wrapper |
| 后台 Runnable 抛异常 | HandlerThread Looper 不终止 | `onSubtitleBitmaps` 两层 try-catch + `buildBitmapArray` 逐块 catch |
| `media` 已释放时注入选项 | 不阻断起播 | 本轮 #7 |
| 文本桥空文本回调与切轨状态不同步 | 无条件隐藏，不残留 | 第二轮空文本分支 + 本轮 #9 |

## core / JNI 侧核查（结论：无需再改码、不重编 AAR）

- JNI `nativeSetSubtitleBitmapListener` 的顺序是**先** `vlc_spu_set_bitmap_listener(NULL,NULL,false)` **后** `DeleteGlobalRef(s_bitmap_listener)`。core 本次新增的「注册/反注册前补发 CLEAR」发生在前者内部，此刻 `s_bitmap_listener` 仍有效；`vlcjni_spu_bitmap_cb` 开头 `if (!env || !s_bitmap_listener) return` 也兜住了并发反注册。
- core `vlc_spu_set_bitmap_listener()` 补发回调前做了 `pf_old && b_old_only && b_old_has_last` 三重判空，且**在 `spu_user_params.lock` 释放之后**调用，不存在同锁重入死锁。
- `SpuRender()` 空队列分支在 `vlc_mutex_unlock(&sys->lock)` 之后才调 `SpuBitmapBridgeNotify(spu, NULL)`，不会持 `sys->lock` 回调 Java。
- `b_has_last` 保证 CLEAR 只补发一次，不会每帧刷屏；`SpuBitmapBridgeNotify` 在 `pf_bitmap` 为空时直接返回。
- JNI `vlcjni_spu_bitmap_cb` 有 `i_count` 上限 16、`pp_rgba[i]` 判空、`CallVoidMethod` 后 `ExceptionClear`。
- JNI 签名修复只是 `([[B[IIIIJJ)V` → `([[B[IIIJJ)V` 单行常量，无异常面。
