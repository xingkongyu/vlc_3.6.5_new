# 2026-11-06 字幕文字边框统一为黑色（原色分离方案）

## 1. 需求与方案选择

需求「字幕中文字边框统一为黑色」。用户确认：

- 覆盖范围：**位图字幕（PGS/DVDSUB）+ 文本字幕两者都要**；
- 实现方式：**A 原色分离**（core 回传原色，App 按亮度把暗像素固定黑、亮像素用设置色；字色设置仍生效），而非「B 黑色外描边」或「C 直接保留原盘配色」。

本次**只改 App**，不动 core、不重编 AAR、不需要构建机。

## 2. 现状与根因

| 链路 | 改动前 |
| --- | --- |
| VLC 内核文本桥 → `vlc/res/layout/vlc_video.xml` 的 `tv_subtitle` | 已有黑边：`shadowColor=#FF000000`、`shadowDx/Dy=1`、`shadowRadius=6` |
| 外挂字幕 `app/res/layout/activity_video2.xml` 的 `subtitle_view` / `text_subtitle` | **没有任何描边**。`VideoActivity2.java:2638-2755` 里带黑色 case 的 `upSubborder()` 整段是注释，从未启用 |
| PGS 位图字幕（App 接管链路） | `vout_subpictures.c:295-330` 的 `SpuBitmapBridgeNotify()` 在 `i_color != 0` 时只保留 alpha、把**整张 RGBA 的 RGB 全替换成用户色**，原盘自带的黑色描边被一起染成字色（设备当时颜色档位 2 = 红色），所以这一路完全没有黑边 |

即「不统一」来自：文本字幕一部分有黑边、一部分没有；位图字幕的黑边被字色吃掉。

### 3.2 `D:\workspace\A14\a14_2\publicversion\app\src\main\res\layout\activity_video2.xml`

给 `subtitle_view`（`com.avery.subtitle.widget.SimpleSubtitleView`，实为 `AppCompatTextView` 子类）与 `text_subtitle` 各补 4 行，与 `vlc_video.xml` 的 `tv_subtitle` 完全一致：


`setTextColor()` 只改字身，`shadowColor` 保持黑色 → 文本字幕同样是「字身跟设置色、边框恒黑」。

## 7. 已知边界与注意

- `SUB_BORDER_LUMA_MAX = 64` 是经验阈值：PGS 调色板若为「非白字身 + 非黑描边」或带灰色抗锯齿，可能需要按片源微调；阈值过高会把抗锯齿误判成黑边（字变细），过低会把暗字身误判成黑边。
- 用户若把字色选为黑色，字身与黑边同为黑色，字幕在亮画面上会难以分辨——这是用户自选颜色的结果，不是本次缺陷。
- 未做（属此前「全下沉 App」架构收尾）：core 的 `spu_SetUserColor` / `SpuUserColorGet` / bridge alpha 遮罩改色等死代码仍在 AAR 中，但现在恒传 0 不会触发；`:sub-scale` 与 `setSubtitleScale()` 对回传位图依旧无效（字号由 App 侧 `userScale` 负责）。
