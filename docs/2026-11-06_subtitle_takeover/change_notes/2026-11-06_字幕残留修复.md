# 2026-11-06 字幕切换 / 切集时字幕残留修复

## 1. 需求与方案

现象：切换字幕轨、或播放下一个视频时，屏幕可能残留上一轨/上一集的最后一句字幕。

用户确认的范围与执行方式：**A（App 侧代际/清屏修复）+ core 根治（补发 CLEAR）**，并且**直接改、编译、装机验证**。

## 2. 第一轮：位图桥与 core 的残留防护

### 2.1 App 侧（`vlc/.../VlcVideo.java`）

| 位置 | 改前 → 改后 |
| --- | --- |
| `hideCustomSubtitle()` 2700 | 开头新增 `mSubtitleGen.incrementAndGet();`，让所有主动清屏入口统一作废在途位图绘制任务（顺序「先作废、再隐藏」） |
| `setSubtitleVisible(false)`、`selectSubTrack(-1)` | `setSpuTrack(-1)` 之后各补一次 `mSubtitleGen.incrementAndGet();`，作废取消选轨期间 vout 渲染的过渡帧 |

## 3. 第二轮：真机日志追出的真正根因（文本字幕链路）

### 3.1 取证

- 用户当时在播 `21个字幕The.Mandalorian...mkv`（`codec=subt` / `subrip` 文本字幕），日志里**完全没有 `bitmap cb` / `bitmap draw`** → 残留不来自 PGS 位图桥。
- App 日志 `onSubtitleText: ... text=[]` 看似文本为空，但该监听器只在 `startMs != sMs && stopMs != eMs` 时打日志（去重），**`mSubtitleHandler.post()` 每次回调都执行** → 文本实际已被设置到 `tv_subtitle`，日志是假象。
- `VLCSpuTrace` 显示切轨时刻（`10:57:23 / 25 / 44 / 53`）只有 `spu-es SELECTED`，没有 `select: none`；而 core 的文本桥空串通知 `spu_text_bridge_update("", 0, 0)` 只在 `SpuRender()` 被调用时发出（2005-2022），切轨瞬间 vout 不渲染新帧 → 没有空串回调。
- 截图实证：设置面板下方残留一行绿色 `That's no life for a kid.`（正是 `setSubtitleColor: -16711936`），属 UI 层自绘 TextView；控件树里 `subtitle` 相关节点均不在（面板是独立 window）。
- **根因**：切轨统一入口 `applyVlcSpuTrack()` 只调 `hideBitmapSubtitle()`（清位图 ImageView），**没有隐藏文本字幕 `tv_subtitle`**；第一轮给 `hideCustomSubtitle()` 加的代际递增因此完全没被切轨路径触发。

### 3.2 修复（仅 `VlcVideo.java`，不需要再动 AAR）

| 位置 | 改前 → 改后 |
| --- | --- |
| `applyVlcSpuTrack()` 2048 | `hideBitmapSubtitle()` → `hideCustomSubtitle()`（同时清文本 TextView、位图 ImageView、作废在途绘制任务） |
| `onSubtitleText()` 空文本分支 249-255 | 原来仅当 `mShownSubtitleText != null` 才隐藏 → 改为无条件 `mShownSubtitleText = null`，并在 View 非 GONE 时 `setText("")` + `setVisibility(GONE)`；避免切轨已清状态、View 仍 VISIBLE 时漏隐藏 |

core 侧文本桥的空串通知本来就在 `SpuRender()` 里（2019 行），缺的是「切轨瞬间 vout 不渲染」时的 App 主动清屏，故本轮无需重编 AAR。
